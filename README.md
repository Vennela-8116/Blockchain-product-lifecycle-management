# RepairChain 🔗

**A Blockchain-Based Lifetime Repair and Ownership Passport for Physical Products**

RepairChain maintains a verifiable digital passport for physical products (laptops, electronics, etc.). It records product registration, ownership transfers, repairs, component replacements, and inspections on a local Ethereum blockchain. Detailed records are stored in MongoDB; cryptographic hashes of those records are anchored on-chain so anyone can independently verify they have not been silently altered.

## Running the Application

Open **three separate terminals**.

### Terminal 1 — Start the local Hardhat blockchain

```bash
cd blockchain
npx hardhat node
```

Keep this running. It starts a local Ethereum node at `http://127.0.0.1:8545` and prints 20 funded test accounts.

### Terminal 2 — Deploy the smart contract & run the seed script

```bash
# Deploy the contract (auto-copies ABI to backend/config/)
cd blockchain
npx hardhat run scripts/deploy.js --network localhost

# The deploy script prints the contract address, e.g.:
#   CONTRACT_ADDRESS=0x5FbDB2315678afecb367f032d93F642f64180aa3
#
# This address is already written to backend/.env by the deploy script.
# If you need to update it manually, edit backend/.env

# Load demo data into MongoDB
cd ..\backend
node scripts/seed.js
```

### Terminal 3 — Start the backend API

```bash
cd backend
npm run dev
```

The API runs at `http://localhost:5000`.

### Terminal 4 — Start the frontend

Open a fourth terminal:

```bash
cd frontend
npm run dev
```

The app opens at `http://localhost:5173`.

## Smart Contract

**File:** `blockchain/contracts/RepairChain.sol`

**Functions:**
- `registerProduct(productId, serialNumber, initialOwner)` — admin only
- `addAuthorizedServiceCenter(address)` — admin only
- `removeAuthorizedServiceCenter(address)` — admin only
- `recordLifecycleEvent(productId, eventHash, eventType)` — authorized service center only
- `initiateOwnershipTransfer(productId, newOwner)` — product owner only
- `acceptOwnershipTransfer(productId)` — pending new owner only
- `cancelOwnershipTransfer(productId)` — current owner only
- `verifyEventHash(productId, index, hash)` — public view

**Security Notes:**
- No personal data, emails, or repair descriptions are stored on-chain
- Only cryptographic hashes of canonical event data are stored
- All write operations are role-restricted
- Backend signs transactions; users do not need MetaMask

## Data Integrity & Blockchain Verification

When an event is recorded:
1. The backend builds a **canonical JSON** string from the event data
2. `keccak256(canonicalJson)` is computed — this is the `eventHash`
3. The hash is submitted to `RepairChain.recordLifecycleEvent()` on the local chain
4. After confirmation, the `txHash` and `blockNumber` are stored in MongoDB
5. Public visitors can see the hash and transaction reference on the Product Passport page

To verify an event independently:
```
GET /api/events/event/:eventId/verify
```
This recomputes the hash from the stored canonical JSON and checks it against the on-chain record.

> **Disclaimer:** Blockchain proves that recorded data has not been silently altered after submission. It does not independently verify that the physical repair was genuinely performed.

## Troubleshooting

| Problem | Solution |
|---|---|
| `MongoDB connection failed` | Start MongoDB: run `mongod` or start the MongoDB service |
| `CONTRACT_ADDRESS not set` | Run the deploy script and update `backend/.env` |
| `RepairChain.json ABI not found` | Run `npx hardhat run scripts/deploy.js --network localhost` in `blockchain/` |
| `ADMIN_PRIVATE_KEY not set` | Check `backend/.env` — it should have the Hardhat Account #0 key |
| Hardhat node not running | Start `npx hardhat node` in the `blockchain/` directory |
| Frontend shows blank page | Check that `npm run dev` is running and `VITE_API_URL` is set |
| Tests fail: login error message mismatch | The test expects `invalid email or password` — the controller returns this exact string |
